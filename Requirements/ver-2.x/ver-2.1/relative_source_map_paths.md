# User Story — Universal Relative Paths for All JSON Output

**Story ID:** US-PARSER-010
**Epic:** EPIC-PARSER-001

### User Story

As a **GASD Tooling Integrator**,
I want **all JSON outputs** generated by the CLI (including standard JSON and Semantic AST via `--json --ast-sem`) to enforce the use of **relative file paths** universally instead of absolute paths,
So that all generated data artifacts are fully portable across heterogeneous environments and guarantee zero leakage of internal absolute file system layouts.

---

### Acceptance Criteria

| ID               | Criteria                                                                                               |
| ---------------- | ------------------------------------------------------------------------------------------------------ |
| AC-PARSER-010-01 | Every file path emitted anywhere in the JSON outputs MUST use a path relative to the Current Working Directory (CWD). |
| AC-PARSER-010-02 | Absolute file paths MUST NOT appear in any field of the JSON payload under any circumstances.          |
| AC-PARSER-010-03 | Path resolution MUST handle cross-platform directory separators correctly, standardizing exclusively on forward slashes `/`. |
| AC-PARSER-010-04 | If a file is located in a parent directory of the CWD, it MUST use standard `../` notation to maintain relativity. |
| AC-PARSER-010-05 | For stdin or virtual files, the file identifier field MUST continue to preserve its designated identifier (e.g., `"stdin"`). |
| AC-PARSER-010-06 | All JSON structural elements (keys, lists, raw values) MUST systematically clean and relativize any absolute paths encountered during serialization ("Zero-Leak" path relativization). |

---

### Acceptance Tests

| Test ID          | Description                                                                  |
| ---------------- | ---------------------------------------------------------------------------- |
| AT-PARSER-010-01 | Run `gasd_parser --json test.gasd` (and optionally with `--ast-sem`) within its directory and verify any `file` paths are `"test.gasd"`. |
| AT-PARSER-010-02 | Run `gasd_parser --json subdir/test.gasd` from the parent and verify paths are logged as `"subdir/test.gasd"`. |
| AT-PARSER-010-03 | Run from a subdirectory (`cd subdir && gasd_parser --json ../test.gasd`) and verify paths are resolved as `"../test.gasd"`. |
| AT-PARSER-010-04 | Verify that on Windows environments, absolute paths like `C:\User\subdir\test.gasd` are actively scrubbed and converted to `subdir/test.gasd` across the entire JSON tree. |
